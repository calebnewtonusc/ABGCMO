description: Diagnose what is actually blocking growth, then give one recommendation
---

Run a full growth diagnosis on $ARGUMENTS (a repo, product, company, or profile).

Follow `skills/growth-diagnosis` exactly:

1. **Gather the real baseline.** If it is a GitHub repo, use `gh` to pull stars,
   forks, topics, license, contributors, and traffic. If it is a live product,
   read the landing page. Do not guess numbers.
2. **Place the stage.** Pre-product, pre-PMF, post-PMF, or scaling, with evidence.
3. **Name the binding constraint** — awareness, comprehension, conversion,
   activation, retention, or referral. Only one is usually binding. Justify it.
4. **Name the hard side** if there is a network.
5. **Check channel-product fit** against `data/channel-economics.md`. If the
   product has no multiplayer surface and no shareable artifact, say plainly that
   it will not go viral.
6. **Compare every number to `data/benchmarks.md`** before calling it a problem.

Output:
- The constraint, and why it and not the others
- **One** highest-leverage action, not a list
- What to expect, by when, with the survivorship caveat
- A stopping rule: what result by what date means this is wrong
- Anything free and permanent being left on the table (topics, license, registry
  listings, profile README)

Carry evidence tags on every number.
